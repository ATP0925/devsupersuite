### Response 1: AST Slicing vs. Vector RAG Chunking
**Community Question**: *"Why use AST slicing when modern tools already use vector embeddings (RAG) for codebase retrieval?"*  
**Maker Response**:
```text
Great question! Vector RAG operates on arbitrary text chunking (e.g. 500-token blocks). In source code, this causes "Syntax Decapitation": chunk boundaries routinely slice methods in half, severing them from parent class imports and generic type bounds. When the LLM receives these amputated chunks, it hallucinates types.

Furthermore, vector search takes 150ms–400ms. OmniKernel 5.2 uses Tree-sitter compilers to construct Concrete Syntax Trees in <1.8ms on local CPU silicon. It retains 100% of interfaces and docstrings while pruning only function bodies. You get deterministic compiler-verified contracts with -83% token payload!
```

### Response 2: Shannon Entropy vs. Regex Secret Scanners
**Community Question**: *"How is AgentShield different from existing pre-commit tools like TruffleHog or Gitleaks?"*  
**Maker Response**:
```text
TruffleHog and Gitleaks rely primarily on regular expression dictionaries matching known vendor prefixes (`sk_live_`, `AKIA`). 

When autonomous agents generate synthetic test scripts, they often hardcode unpatterned custom tokens or raw base64 credentials that match no regex. Worse, regexes matching generic strings trigger massive false-alarm fatigue on UUIDs and Git commit hashes.

AgentShield calculates Claude Shannon's Information Entropy ($H > 4.5\text{ bits/char}$) in CPU SIMD registers (<0.8ms). UUIDs are constrained to 16 hex chars ($H \le 3.6$), while cryptographic keys exceed 4.5. It achieves virtually zero false alarms on UUIDs while catching 100% of random keys locally before git staging!
```

### Response 8: Dynamic Python Type Handling & Docstrings
**Community Question**: *"How does AST slicing handle dynamically typed Python without type annotations?"*  
**Maker Response**:
```text
In untyped Python, OmniKernel preserves parameter default values (`def connect(timeout=30)`), `*args/**kwargs`, and docstring type specifications (`:param str user_id:`). It inspects return statements to emit stubbed signatures (`def get_session(...) -> dict: ...`). Even in untyped Python, prompt tokens decrease by 72%–78% while preserving public method boundaries.
```

### Response 9: Rust Macros & C++ Concepts / Templates
**Community Question**: *"What happens with Rust derive macros or complex C++20 templates?"*  
**Maker Response**:
```text
Tree-sitter produces a Concrete Syntax Tree that treats macro attributes (`#[derive(Serialize)]`, `#[tokio::main]`) and `macro_rules!` as atomic structural nodes. They are never truncated. In C++20, template headers and `requires` concept constraints are preserved as part of the signature, and only the `{ ... }` compound body is replaced with `;`.
```
