Which Tree-sitter query pattern represents the most optimal OmniKernel AST extraction rule?*

- **B)** `(template_declaration (concept_definition) @keep) (class_specifier body: (field_declaration_list (access_specifier) "public" (field_declaration) @keep_field))`
- **C)** `(function_definition body: (compound_statement) @strip)`
- **D)** `(translation_unit (_)* @dump)`
- **Correct Answer: B**.
- *Explanation*: OmniKernel's AST Context Slicer traverses class specifiers with public access specifiers to preserve type signatures while explicitly targeting internal `compound_statement` bodies for stubbing, eliminating implementation bloat while keeping concept bounds intact.

#### Question 2 (Module 2 - Shannon Entropy Register Mathematics):

- **A)** Hardware SIMD registers cannot calculate logarithms below 4.0.
- **B)** Standard 32-character hexadecimal UUIDs draw from a 16-character alphabet ($\log_2 16 = 4.00$), meaning UUIDs measure $H \le 4.00$, whereas base-64/base-58 keys measure $H \ge 4.50$.
- **C)** The POSIX standard forbids entropy thresholds below 4.50.
- **D)** It accelerates AVX-512 vector pipelines.
- **Correct Answer: B**.
- *Explanation*: Setting the threshold at $4.50$ mathematically eliminates false positives from UUIDs, Git commit SHA-1/SHA-256 hashes, and database primary keys, while reliably capturing high-entropy cryptographic keys (Stripe, OpenAI, AWS, GitHub tokens).
